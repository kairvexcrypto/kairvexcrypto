# YAML читается, но плагин не работает: проверяем смысл настроек

Отступы — только одна из причин проблем с конфигурацией. Файл может успешно разбираться как YAML и при этом содержать строку вместо числа, отрицательный лимит или отсутствующее поле, которое понадобится только в конкретном режиме.

Для таких случаев в ConfigDoctor используются отдельные правила. Плагин читает указанный файл и проверяет значения, не изменяя его.

```yaml
version: 1
profiles:
  arena:
    file: Arena/config.yml
    rules:
      - path: /players/max
        type: integer
        required: true
        min: 2
        max: 100
      - path: /arena/world
        type: string
        required: true
        min-length: 1
        when:
          path: /mode
          equals: arena
```

Здесь первое правило проверяет лимит игроков. Второе требует имя мира только при `mode: arena`. Если поля нет в режиме выживания, это не станет ложной ошибкой.

После изменения правил выполняем `/cdoc reload`, затем `/cdoc check arena` и `/cdoc report`. Код REQUIRED означает отсутствие поля, TYPE — неподходящий тип, MIN или MAX — выход за допустимый диапазон. Отдельная ошибка YAML указывает на проблему разбора файла.

Если новая схема правил повреждена, ConfigDoctor сохраняет действующую. Это помогает избежать ситуации, когда опечатка администратора внезапно отключает все проверки. После исправления схемы её нужно загрузить повторно.

В отчёте есть путь поля и причина нарушения, но нет самого значения. Например, слишком длинный токен не должен целиком попасть в чат или экспорт. При этом сами пути тоже нужно выбирать аккуратно: секретам не место в названиях ключей и профилей.

У проверки есть предел: она ничего не знает о скрытой логике стороннего плагина и не видит его текущие настройки в памяти. Положительный отчёт означает, что файл соответствует заданным правилам. Запуск сервера, вход игрока и проверку механики он не заменяет.
